# روش آزمون شبکه در ۲.۵.۳

## هدف

اندازه‌گیری از **مرورگر همان کاربر**، بدون جایگزین‌کردن مسیر سرور خارجی به‌جای اینترنت او. اگر VPN/پروکسی فعال باشد، مسیر اندازه‌گیری شامل آن است.

## آزمون‌های پیاده‌سازی‌شده

- **پایه:** پنج GET بدون cache به `/api/ping`، با بررسی JSON و نسخه. میانهٔ زمان پاسخ، نوسان میانهٔ اختلاف نمونه‌های موفق و درصد درخواست‌های بی‌پاسخ گزارش می‌شود؛ این درصد packet loss واقعی TCP/ICMP نیست.
- **WebSocket:** ارتباط واقعی به `/api/network/ws`، پنج پیام nonceدار و زمان رفت‌وبرگشت؛ endpoint فقط پیام تست محدود را echo می‌کند، Origin را کنترل می‌کند و پروکسی TCP نیست.
- **پورت‌ها:** 443، 2053، 2083، 2087، 2096 و 8443 روی hostname همین Worker؛ بررسی پاسخ سلامت همان نسخه، نه پاسخ یک میزبان نامرتبط. پشتیبانی شبکهٔ عمومی کلادفلر به معنی فعال‌بودن همهٔ این پورت‌ها برای هر Worker نیست.
- **DoH:** پاسخ JSON معتبر با Answer برای Cloudflare و Google؛ پاسخ wire-format معتبر برای Quad9. آزمون DoH، آزمون کامل دست‌کاری DNS اپراتور نیست.
- **انتقال:** سه نمونهٔ ۱۲۸ کیلوبایتی برای هر جهت؛ دادهٔ تصادفی برای کاهش اثر فشرده‌سازی ساده. هم‌زمان با انتقال، نمونهٔ تأخیر گرفته می‌شود. این اندازه و مدت برای تشخیص قطعی سقف سرعت، MTU یا Bufferbloat کافی نیست.
- **IP و دامنه:** سه درخواست HTTPS مستقیم از مرورگر، هم‌زمانی محدود و timeout. پاسخ اکثریت برای رتبه‌بندی مثبت لازم است. مدت تلاش ناموفق جدا از RTT پاسخ موفق نمایش داده می‌شود. هیچ درخواست اسکن IP به سرور پنل برای «اندازه‌گیری از خارج کشور» منتقل نمی‌شود.

## چرا خطای سریع، IP سالم نیست؟

مرورگر، دلایل TLS، CORS، قطع ارتباط، سیاست امنیتی و بعضی خطاهای شبکه را معمولاً به شکل TypeError مشابه برمی‌گرداند. بنابراین سریع‌بودن رد درخواست به‌تنهایی، معیار تأیید سلامت یا latency موفق نیست. IP خام ممکن است بدون SNI دامنهٔ اشتراک خطای گواهی بدهد؛ این خطا، خراب‌بودن IP در کلاینت واقعی را هم ثابت نمی‌کند. برای همین نتیجهٔ خطا حذف یا به IP سالم تبدیل نمی‌شود.

## سیاست پیشنهاد تنظیمات

- اصلاح ALPN نامناسب برای WS و پیشنهاد پایهٔ سازگاری فقط در صورت دریافت پاسخ کافی از Worker.
- پیشنهاد Early Data صفر در مشاهدهٔ بی‌ثباتی WS/آپلود؛ این یک آزمایش قابل‌بازگشت است، نه تشخیص قطعی محدودیت اپراتور.
- حفظ DNS انتخابی، پورت‌های TLS، IPها و قواعد شخصی؛ نمایش مشاهده‌ها برای تصمیم آگاهانه.
- Fragment در مرورگر آزموده یا به‌طور خودکار «بهینهٔ قطعی» اعلام نمی‌شود. پارامترهای پیشنهادی باید با هستهٔ واقعی و شبکهٔ مقصد آزمایش شوند.
- تنظیمات فقط پس از تأیید مدیر ذخیره می‌شوند. هیچ تغییر به‌صورت خودکار بر اساس «فیلتر بودن قطعی سایت» یا «تحریم قطعی IP» اعمال نمی‌شود.
