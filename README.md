# 🤖 Armando Group Manager — آرماندو

ربات مدیریت گروه تلگرام، **فارسی‌محور**، ماژولار و آمادهٔ استقرار (Railway).
ساخته‌شده با **Python 3.12+** و **aiogram 3.31** — کد کاملاً اورجینال، بدون کپی از ربات‌های موجود.

> همهٔ متن‌های ربات (دکمه‌ها، پیام‌ها، خطاها، راهنما، پنل، آمار) **فارسی** است.
### شیوهٔ تشخیص دستورات
ربات فقط زمانی واکنش نشان می‌دهد که پیام **خودِ دستور** باشد:

| پیام | نتیجه |
| --- | --- |
| `قیمت دلار` | ✅ اجرا می‌شود |
| `قیمت دلار چقدر گرون شده` | ❌ گفتگوی عادی — واکنش نشان نمی‌دهد |
| `بن ۲روز تبلیغ` | ✅ اجرا می‌شود |
| `بن کردن این کار لازمه` | ❌ گفتگوی عادی |

دستوراتی که آرگومان نمی‌گیرند (`تاریخ`، `ارز دیجیتال`، `پنل` …) باید **دقیقاً همان عبارت** باشند.

## 🚀 اجرای سریع (لوکال)

```bash
git clone <repo> armando && cd armando
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env      # سپس BOT_TOKEN و OWNER_ID را پر کنید
python -m app.main
```

پیش‌فرض **Long Polling** است. برای وب‌هوک کافی است در `.env` مقدار
`USE_WEBHOOK=true` و `WEBHOOK_URL=https://your-domain` را تنظیم کنید
(سرور داخلی روی پورت `WEBAPP_PORT` بالا می‌آید و مسیر `/health` برای Health-check دارد).

### دریافت `OWNER_ID`
عددی است که از `@userinfobot` (فیلد Id) می‌گیرید. این شناسه فقط برای
**دستورات سطح مالک ربات** است (آمار، پیام همگانی، بن/سکوت سراسری و واگذاری اختیارات روت).
برای یک ربات **عمومی** که بقیه به گروه خودشان اضافه می‌کنند، می‌توانید آن را
خالی بگذارید؛ مدیریت هر گروه بر اساس **دسترسی‌های واقعی تلگرام** انجام می‌شود
(سازنده و ادمین‌های هر گروه).

## 🛰 استقرار روی Railway (توصیه‌شده)

1. یک پروژهٔ جدید در Railway بسازید و مخزن (Repository) را متصل کنید — یا پوشه را با Railway CLI آپلود کنید:
   ```bash
   railway login && railway init && railway up
   ```
2. **Variables** را در بخش Variables پروژه اضافه کنید (معادل همان فایل `.env`):
   - `BOT_TOKEN` — توکن از @BotFather (**اجباری**)
   - `OWNER_ID` — شناسه عددی شما (**اجباری**)
   - `ENVIRONMENT=production`, `LOG_LEVEL=INFO`, `TIMEZONE=Asia/Tehran`
3. (**توصیه می‌شود**) یک **Volume** با مسیر `/app/data` به سرویس وصل کنید تا دیتابیس SQLite بین ری‌استارت‌ها باقی بماند.
   - اگر حجم پیام بالاست، به‌جای آن سرویس **Postgres** اضافه کنید و مقدار `DATABASE_URL` را از آن کپی کنید
     (ربات به‌طور خودکار `postgresql://…` را به `postgresql+asyncpg://…` تبدیل می‌کند).
4. Railway به‌طور خودکار `railway.toml` را می‌خواند؛ دستور شروع `python -m app.main` است و
   Health-check روی مسیر `/health` تنظیم شده است. (اگر از وب‌هوک استفاده می‌کنید،
   `USE_WEBHOOK=true` و `WEBHOOK_URL` را هم تنظیم کنید و پورت را آزاد بگذارید.)
5. دکمهٔ **Deploy** را بزنید. در لاگ‌ها باید پیام آماده‌به‌کار ربات را ببینید.
6. ربات را به گروه اضافه و **ادمین** کنید (دسترسی‌های حذف پیام و محدودسازی لازم است)،
   سپس در گروه بنویسید: `پنل`

> نکته: برای اجرای وب‌هوک در Railway، در تنظیمات سرویس گزینهٔ **Public Networking → Generate Domain**
> را فعال کنید و همان آدرس را در `WEBHOOK_URL` بگذارید.

## 🧹 اسکن حساب‌های حذف‌شده

اسکن از MTProto می‌خواند و فقط وقتی فیلد رسمی `User.deleted` برابر است، شناسه را هدف می‌گیرد؛ نام نمایشی به‌تنهایی مبنای بن نیست. صفحه‌بندی کانال تا ۵۰۰ صفحهٔ ۲۰۰عضوی (حدود ۱۰۰٬۰۰۰ عضو) پیش‌فرض است و با `DELETED_ACCOUNT_MAX_PAGES` قابل تنظیم است. فهرست اعضا ممکن است به‌خاطر دسترسی، نوع کانال یا محدودیت تلگرام ناقص باشد؛ خطای هر چت به مالک گزارش می‌شود، و موفقیت بن فقط با پاسخ موفق تلگرام ثبت می‌شود.

برای کانال‌هایی که نشست ربات اجازهٔ خواندن فهرست اعضا را ندارد، نشست کاربری MTProto را یک‌بار روی دستگاه مورداعتماد بسازید. فرمان زیر API ID و Hash را در ترمینال می‌گیرد و نشست را چاپ می‌کند؛ خروجی را فقط در متغیر Railway با نام `TELEGRAM_SESSION_STRING` به‌صورت **Secret** قرار دهید. آن را در پیام، مخزن، `.env.example` یا ZIP نگذارید و حساب را به چت‌های موردنیاز اضافه کنید:

```bash
python - <<'PY'
from telethon import TelegramClient
from telethon.sessions import StringSession

api_id = int(input("API ID: "))
api_hash = input("API HASH: ").strip()
with TelegramClient(StringSession(), api_id, api_hash) as client:
    client.start()
    print(client.session.save())
PY
```

`TELEGRAM_API_ID` و `TELEGRAM_API_HASH` نیز باید در Railway تنظیم شوند؛ Hash و Session را Secret نگه دارید. بدون نشست کاربری، ربات با نشست Bot API تلاش می‌کند، اما پوشش کامل تضمین نیست. بات باید در گروه/کانال دسترسی لازم برای مسدودکردن اعضا داشته باشد؛ برای گزارش خصوصی خطاها، مالک باید یک‌بار `/start` را بزند.

## 💬 گفت‌وگوی هوشمند گروه/کانال با API عمومی سازگار با OpenAI

این قابلیت به سرویس‌دهندهٔ مشخصی وابسته نیست و از هر API سازگار با OpenAI استفاده می‌کند. سرویس باید مسیرهای `GET /v1/models` و `POST /v1/chat/completions` (یا مسیرهای معادل زیر پیشوند سفارشی خودش) را با `Authorization: Bearer …` پشتیبانی کند. اگر `AI_CHAT_BASE_URL` فقط دامنه باشد، ربات `/v1` را خودکار اضافه می‌کند؛ اگر نشانی از قبل مسیر `/v1` یا مسیر API سفارشی داشته باشد، همان را حفظ می‌کند. فهرست نام و شناسهٔ مدل‌ها مستقیماً از API خوانده می‌شود. این قابلیت از «تحلیل هوشمند پیام‌ها» برای نظارت مدیریتی جداست.

### راه‌اندازی امن در Railway

1. از provider دلخواه خود یک API key بگیرید؛ API باید با OpenAI Chat Completions سازگار باشد.
2. در Railway وارد **سرویس ربات → Variables** شوید و این دو متغیر را ثبت کنید:
   - `AI_CHAT_BASE_URL` — آدرس پایهٔ API. برای TokenRouter می‌توانید `https://api.tokenrouter.com` یا `https://api.tokenrouter.com/v1` بگذارید؛ در حالت دامنهٔ تنها، ربات `/v1` را اضافه می‌کند. مسیرهایی مثل `/chat/completions` را وارد نکنید؛ ربات خودش اضافه می‌کند.
   - `AI_CHAT_API_KEY` — کلید را به‌عنوان **Secret** ثبت کنید؛ در گفتگو، سورس، `.env.example`، ZIP یا لاگ نگذارید.
3. سرویس را Deploy/Restart کنید. انتخاب مدل پیش‌فرض لازم نیست؛ `AI_CHAT_DEFAULT_MODEL` اختیاری است و فقط برای گفت‌وگوی خصوصی ربات کاربرد دارد.
4. در هر گروه یا کانالی که ربات ادمین است، مدیر از مسیر **پنل → تنظیمات → گفت‌وگوی هوشمند** مدل همان چت را جداگانه انتخاب کند. فهرست مدل‌ها زنده از API دریافت می‌شود.
5. در گروه یا کانال، پیام را با `آرماندو` آغاز کنید؛ برای ادامه روی پاسخ آرماندو ریپلای کنید. مدیر می‌تواند حافظهٔ اختیاری را روشن کند؛ در آن صورت فقط پیام‌هایی که تلگرام به ربات می‌رساند تا ۷ روز نگهداری و سپس خودکار پاک می‌شوند.

آرماندو با هویت Bot API خودش فقط می‌خواند و پاسخ می‌دهد؛ بن، سکوت، حذف یا تغییر تنظیمات انجام نمی‌دهد. Bot API تاریخچهٔ پیش از افزودن ربات را نمی‌دهد و دریافت پیام‌های گروه به تنظیمات privacy و سطح دسترسی ربات وابسته است. APIهای ناسازگار با OpenAI به adapter جداگانه نیاز دارند.

## 📥 دریافت رسانه از اینستاگرام

ربات برای لینک‌های مستقیم پست/ریل ابتدا از استخراج‌گرهای متن‌باز استفاده می‌کند؛
اگر خطای ورود یا محدودیت مخاطب دریافت شود، نشست مجاز مالک می‌تواند تلاش جایگزین
انجام دهد. در گفت‌وگوی خصوصی، فقط خود مالک می‌تواند این تلاش را راه بیندازد؛ در
گروه، هر عضو انسانی می‌تواند لینک بدهد، مشروط به اینکه پیام از دروازهٔ مجاز گروه
بات عبور کند. اگر `REQUIRE_GROUP_APPROVAL=true` باشد، گروه باید پیش‌تر تأیید شده
باشد؛ اگر خاموش باشد، بات در گروه‌هایی که معمولاً می‌پذیرد فعال است.

کوکی فقط وقتی مفید است که همان حساب خودش مجاز به دیدن همان پست باشد؛ محدودیت واقعی
سن/منطقه یا دسترسی خصوصی را تضمینی رفع نمی‌کند. برای کاهش ریسک، از حساب اینستاگرام
ثانویه استفاده کنید و اجازه ندهید افراد ناشناس در گروه‌های عمومی این نشست را به
کار بگیرند.

در صورت نیاز، از نشست خود فایل کوکی **Netscape** صادر کنید و محتوایش را به Base64
تبدیل کنید؛ مقدار را فقط به‌عنوان Secret محیط استقرار ثبت کنید:

```env
INSTAGRAM_COOKIES_B64=<Base64 of Netscape cookies.txt>
```

کوکی مانند رمز ورود محرمانه است: آن را در مخزن، پیام تلگرام، گزارش یا لاگ نگذارید.
در صورت افشا، نشست را از تنظیمات اینستاگرام خارج و کوکی تازه صادر کنید. فایل موقت
کوکی دسترسی `0600` دارد و پس از پایان دریافت پاک می‌شود. دانلود و دسترسی به همهٔ
پست‌ها تضمین‌شده نیست.

## 📢 مسدود کردن کانال‌ها (`banChatSenderChat`)

وقتی کسی **با نام کانال** در گروه پیام می‌فرستد، بن کردن حساب کاربری فایده‌ای
ندارد — هویتِ کانال همچنان در گروه می‌ماند. برای این حالت دو دستور وجود دارد:

| دستور | کاربرد |
| --- | --- |
| `بن کانال` | مسدود کردن کانالی که پیام با آن فرستاده شده (با ریپلای) |
| `رفع بن کانال` | آزاد کردن کانال مسدود شده |

همچنین اگر روی پیامِ یک کانال، دستور «بن» یا «اخراج» بزنید، ربات به‌طور خودکار
کانال را هم مسدود می‌کند.

> ⚠️ **دو محدودیت مهم که باید بدانید** (بر اساس مستندات رسمی Bot API):
> 1. این قابلیت فقط در **سوپرگروه** کار می‌کند، نه گروه معمولی.
> 2. مسدود کردن یک کانال باعث می‌شود مالک آن نتواند با **هیچ‌یک از** کانال‌هایش
>    در آن گروه پیام بفرستد — نه فقط همان کانال. برای آزادسازی از
>    `رفع بن کانال` استفاده کنید.
>
> کانالِ متصل به خودِ گروه را نمی‌توان مسدود کرد (تلگرام خطا می‌دهد)؛
> ربات این حالت را تشخیص می‌دهد و از قبل جلوگیری می‌کند.

## 🔐 دروازهٔ تایید گروه (اختیاری)

به‌طور پیش‌فرض آرماندو یک **ربات عمومی و چندمستأجره** است: هر کسی آن را به
گروهش اضافه کند، بلافاصله کار می‌کند.

اگر ترجیح می‌دهید هیچ گروهی بدون تایید شما فعال نشود، این دروازه را روشن کنید:

```env
REQUIRE_GROUP_APPROVAL=true
OWNER_ID=123456789      # الزامی است، وگرنه پیامی ارسال نمی‌شود
```

رفتار در این حالت:

1. با افزوده شدن ربات به یک گروه، یک پیام خصوصی همراه با دکمه‌های
   ✅ تایید / ❌ رد برای مالک ارسال می‌شود؛
2. تا پیش از تایید، ربات در آن گروه هیچ دستوری را اجرا نمی‌کند و فقط یک بار
   پیام «ربات هنوز فعال نشده است» نشان می‌دهد؛
3. با رد شدن، ربات از گروه خارج می‌شود.

دستورات مالک (در چت خصوصی):

| دستور | کاربرد |
| --- | --- |
| `تایید گروه -1001234567890` | تایید دستی یک گروه |
| `رد گروه -1001234567890` | رد و خروج از گروه |
| `وضعیت تایید` | نمایش وضعیت دروازه |

> این ویژگی **پیش‌فرض خاموش** است تا رفتار عمومی ربات تغییر نکند.

## 🔎 اطلاعات گروه و کانال

دستور `آیدی گروه` (با نام‌های دیگر: `شناسه گروه` / `ایدی گروه` /
`اطلاعات گروه` / `اطلاعات کانال`) اطلاعات کامل چت را نمایش می‌دهد:

- نوع چت (گروه معمولی / سوپرگروه / کانال / چت خصوصی)
- عنوان و شناسه عددی
- **عمومی یا خصوصی** بودن و نام کاربری (بدون نمایش لینک دعوت یا شناسهٔ شخصی)
- تعداد اعضا (یا دنبال‌کنندگان برای کانال)
- توضیحات چت

دو شیوهٔ استفاده:

| شیوه | نمونه |
| --- | --- |
| بدون آرگومان | `آیدی گروه` → اطلاعات همین گروه |
| با نام کاربری یا شناسه | `آیدی گروه @mychannel` یا `آیدی گروه -1001234567890` |

> ⚠️ **محدودیت تلگرام (نه محدودیت ربات):** ربات فقط می‌تواند چت‌هایی را ببیند که
> **عضو آن‌هاست**. برای چت‌هایی که ربات در آن‌ها نیست، فقط **عمومی**‌ها
> (دارای نام کاربری) قابل بررسی‌اند؛ چت خصوصی را تلگرام اصلاً تحویل نمی‌دهد.
> در این حالت ربات پیام راهنمایی مناسب نشان می‌دهد.

> برای جلوگیری از اشتباه، فقط «یک تک‌واژه» به عنوان آرگومان پذیرفته می‌شود؛
> جملاتی مثل «آیدی گروه چنده» دستور محسوب نمی‌شوند.

## 🔑 مدل دسترسی (مهم)

1. **دسترسی واقعی تلگرام اول است:** سازنده و مدیران هر گروه می‌توانند هر کاری که
   «خود ربات» اجازه دارد انجام دهند (بن، سکوت، پاکسازی، ارتقا/تنزل مدیر، ساخت لینک،
   تغییر نام و توضیحات گروه …) — بدون نیاز به ثبت نقش داخلی.
2. **نقش‌های داخلی فقط اضافه می‌کنند:** برای همکارانی که ادمین تلگرام نیستند
   (ناظر، کمک‌یار، پاکساز …) و هرگز دسترسی یک مدیر واقعی را کم نمی‌کنند.
3. اگر تلگرام وضعیت را ندهد (مدیر ناشناس، خطای موقت شبکه)، ربات جلوی کار را
   نمی‌گیرد و خود تلگرام تصمیم می‌گیرد.
4. وضعیت اعضا حداکثر ۲ دقیقه کش می‌شود؛ در صورت رد شدن یک دستور، کش بلافاصله
   پاک می‌شود و تلاش بعدی وضعیت تازه را می‌خواند.

### 🏷 تگ اعضا و ارتقا/تنزل مدیر

برای این دو کار، ربات علاوه بر «مدیر بودن» به دو دسترسی مشخص نیاز دارد:

| دستور | دسترسی لازمِ ربات در تلگرام | مسیر فعال‌سازی |
| --- | --- | --- |
| `تگ …` (عضو عادی) | **مدیریت تگ اعضا** (`can_manage_tags`) | تنظیمات گروه ← مدیران ← ربات |
| `تگ …` (روی مدیر) | **افزودن مدیر جدید** (`can_promote_members`) | همان مسیر |
| `ارتقا` / `تنزل` | **افزودن مدیر جدید** (`can_promote_members`) | همان مسیر |

* تگِ اعضای عادی با متد رسمی `setChatMemberTag` در لیست اعضای تلگرام درج می‌شود.
* عنوانِ مدیران فقط برای مدیرانی که **خود ربات** آن‌ها را ارتقا داده باشد قابل
  تنظیم است (`setChatAdministratorCustomTitle`)؛ پیام ربات در غیر این صورت
  دقیقاً همین را می‌گوید.
* دستور `دسترسی ربات` فهرست همهٔ دسترسی‌های ربات را با ✅/❌ نشان می‌دهد؛
  در صورت نقص، پیامِ هر دستور دقیقاً همان دسترسیِ کم‌شده را نام می‌برد.

### 🔒 قفل کلی گروه (دسترسی ارسال اعضا)

قفل‌های محتوایی (لینک، عکس، فحاشی …) پیام را حذف می‌کنند؛ «قفل گروه» یک سطح
بالاتر است و با `setChatPermissions` اجازهٔ ارسال را در سطح تلگرام می‌بندد:

| دستور | نتیجه |
| --- | --- |
| `قفل گروه` | فقط مدیران می‌توانند پیام بفرستند |
| `قفل گروه رسانه` | متن آزاد، اما عکس/فیلم/ویس/فایل/استیکر/نظرسنجی بسته |
| `باز کردن گروه` | بازگشت به حالت عادی |
| `وضعیت قفل گروه` | نمایش وضعیت فعلی (باز / رسانه / کامل / سفارشی) |

همین سه دکمه در پنلِ «🔒 قفل‌ها» هم هستند. پیش‌نیاز: دسترسی «محدود کردن اعضا»
برای ربات.

### 🎯 هدفِ دستور: ریپلای **یا** نام‌کاربری/شناسه

هر دستور مدیریتی هدفش را از ریپلای، `@username` یا شناسهٔ عددی می‌گیرد:

```
لغو سکوت @Parhannni
رفع بن 123456789
ارتقا @username
تاریخچه @username
```

(یک توکنِ کاملاً عددی شناسه حساب می‌شود، نه نام‌کاربری؛ جمله‌هایی مثل
«لغو سکوت الان انجام بده» همچنان دستور شناخته نمی‌شوند.)

### 🚪 قفل خروج (بن خودکار هنگام خروج)

| دستور | نتیجه |
| --- | --- |
| `قفل خروج` | هر کس گروه را ترک کند، همان لحظه بن می‌شود |
| `بن خروج سریع ۱۰` | کسی که تا ۱۰ ثانیه پس از ورود خارج شود بن می‌شود |
| `بن خروج سریع ۰` | خاموش کردن قانون خروج سریع |
| `وضعیت خروج` | نمایش وضعیت |

هر دو قانون به‌طور پیش‌فرض **خاموش** هستند و فقط با دستورِ مدیر روشن می‌شوند؛
مدیران هرگز مشمول آن نمی‌شوند. خروج از رویداد عضویت تلگرام تشخیص داده می‌شود و
بن با زمان `0` (دائمی) ثبت می‌شود. در سوپرگروه، همان حساب تا رفع‌بن توسط مدیر با
لینک دعوت برنمی‌گردد؛ در گروه معمولی تضمین مشابهی از تلگرام وجود ندارد.
بعد از هر بن، ربات یک پیام می‌فرستد با دکمه‌های شیشه‌ای «↩️ رفع بن» و
«⛔️ خاموش کردن این قانون». همین تنظیمات در پنل «🔒 قفل‌ها» هم با دکمه‌های
روشن/خاموش و تنظیم ثانیه در دسترس است.

### 🔒 بن ماندگار (جلوگیری قطعی از بازگشت)

به‌طور پیش‌فرض هر بار که کاربری **بن** یا **اخراج** می‌شود، رفعِ بن انجام
نمی‌شود. در **سوپرگروه**، تلگرام تا وقتی مدیر `رفع بن` نزند، ورود دوبارهٔ همان حساب
با لینک دعوت را مسدود می‌کند. در گروه معمولی این تضمین از طرف تلگرام وجود ندارد.
اگر ربات رویداد ورود دوباره را دریافت کند، دوباره بن می‌کند و علت را در گروه
اعلام می‌کند. مدیر گروه با رفع‌بن می‌تواند اجازهٔ بازگشت بدهد.

| دستور | نتیجه |
| --- | --- |
| `بن ماندگار` | روشن/خاموش کردن این رفتار (پیش‌فرض: **روشن**) |
| `رفع بن` | تنها راهِ بازگشت کاربر |

### 🔄 اعلام تغییر نام و آیدی

تلگرام هنگام تغییر نام یا آیدیِ کاربران **هیچ آپدیتی** نمی‌فرستد. ربات هر پیام
را با رکورد ذخیره‌شده مقایسه می‌کند و به‌محض تفاوت، در گروه اعلام می‌کند:

```
🔄 تغییر مشخصات کاربر

👤 از حسن با آیدی @hassan73273
👤 به محمد با آیدی @muhammad346456
🔗 آیدی: @hassan73273 → @muhammad346456
🆔 شناسه: 123456789
```

| دستور | نتیجه |
| --- | --- |
| `اعلام تغییر نام` | روشن/خاموش کردن اعلام تغییر نام (پیش‌فرض: روشن) |
| `اعلام تغییر آیدی` | روشن/خاموش کردن اعلام تغییر آیدی (پیش‌فرض: روشن) |

برای صرفه‌جویی در منابع، هر کاربر در هر گروه حداکثر هر ۲۰ ثانیه یک‌بار بررسی
می‌شود و رکورد بلافاصله به‌روزرسانی می‌شود، بنابراین یک تغییر **دوبار** اعلام
نمی‌شود.

### ✅ پذیرش خودکار درخواست عضویت

در گروه‌هایی که «تأیید مدیر» برای ورود لازم است، تلگرام برای هر متقاضی یک
`chat_join_request` می‌فرستد. با فعال‌بودن این گزینه ربات بلافاصله آن را
می‌پذیرد:

| دستور | نتیجه |
| --- | --- |
| `پذیرش خودکار` | روشن/خاموش کردن پذیرش خودکار |

ربات برای این کار به دسترسی **«افزودن کاربران»** نیاز دارد. کاربرانی که بنِ
سراسری دارند، به‌جای پذیرش **رد** می‌شوند.

> این گزینه به‌طور پیش‌فرض **خاموش** است، چون پذیرشِ خودکارِ همهٔ افراد یک
> تصمیم امنیتی است و بهتر است آگاهانه روشن شود.

### 📣 تگ همه (منشن همهٔ اعضا)

با دستور `تگ همه` (یا `منشن همه` / `@all` / `صدا زدن همه` / `تگ اعضا`) ربات
**تمام اعضای شناخته‌شدهٔ گروه را منشن می‌کند** — طوری که هر کدام واقعاً
نوتیفیکیشن بگیرند:

```
تگ همه
```

* فقط **مدیران** می‌توانند این دستور را اجرا کنند (سازنده و ادمین‌های گروه،
  حتی اگر مالکِ ربات نباشند).
* محدودیتِ زمانی ندارد؛ هر چند بار پشت‌سر‌هم بخواهید کار می‌کند.
* **هر عضو واقعاً نوتیفیکیشن می‌گیرد.** تلگرام فقط به **۵ منشنِ اولِ هر پیام**
  نوتیفیکیشن می‌فرستد (و حداکثر ۵۰ منشن در یک پیام جا می‌شود)، بنابراین ربات
  اعضا را در **دسته‌های ۵تایی** و در چند پیام پشت‌سر‌هم می‌فرستد
  (مثلاً ۱۲ عضو = ۳ پیام) و بالای هر پیام شمارهٔ بخش را می‌نویسد.
  به همین دلیل منشن‌ها به‌صورت **موجودیتِ واقعی `text_mention`** همراه با
  آبجکتِ کاربر فرستاده می‌شوند، نه صرفاً یک لینکِ `tg://user?id=`؛ لینک ساده
  در بسیاری از مواقع هیچ نوتیفیکیشنی ایجاد نمی‌کند.
  پیام‌های منشن عمداً **بدون `parse_mode`** ارسال می‌شوند: ربات به‌طور پیش‌فرض
  HTML می‌فرستد و اگر `parse_mode` و `entities` با هم بروند، تلگرام متن را
  دوباره به‌عنوان HTML پارس می‌کند و موجودیت‌های منشن را دور می‌ریزد — یعنی
  هیچ نوتیفیکیشنی ارسال نمی‌شود.

**ربات چطور اعضا را می‌شناسد؟** تلگرام لیست اعضا را در اختیار ربات نمی‌گذارد،
برای همین ربات از **همهٔ سیگنال‌های موجود** یک فهرست می‌سازد
(`app/services/roster.py`):

| منبع | چه کسانی اضافه می‌شوند |
| --- | --- |
| پیام و دستور | هر کسی که در گروه چیزی بنویسد |
| پیام‌های سرویسی | هر کسی که وارد شود |
| `chat_member` | کسی که ادمین‌ها محدود/ارتقا/آزادش کنند (حتی اگر حرفی نزده باشد) |
| واکنش (Reaction) | اعضای ساکتی که فقط ری‌اکت می‌زنند |
| `getChatAdministrators` | **همهٔ مدیران گروه** — تنها لیستی که تلگرام واقعاً می‌دهد |
| جدول فعالیت | کسانی که قبلاً پیام داده‌اند (تاریخچه) |

کسانی که گروه را ترک کرده یا بن شده‌اند، و ربات‌ها، منشن نمی‌شوند. هرچه ربات
مدت بیشتری در گروه باشد (و **Volume در Railway** متصل باشد تا دیتابیس با هر
استقرار پاک نشود)، این فهرست کامل‌تر می‌شود. اگر ربات در گروه **ادمین نباشد**،
تلگرام پیام‌ها را به آن نمی‌رساند: در این صورت `@BotFather` → `/setprivacy` →
**Disable** را بزنید و ربات را یک‌بار از گروه حذف و دوباره اضافه کنید.

### 🌐 قفل زبان، پیام طولانی و ارسالِ ناشناس

سه قفلِ درخواستیِ جدید در کنار بقیهٔ قفل‌های محتوایی، با همان دستور `قفل`:

| دستور | نتیجه |
| --- | --- |
| `قفل چینی` | پیام‌های دارای خط چینی/کانجی → حذف + سکوت فرستنده |
| `قفل روسی` | پیام‌های دارای الفبای سیریلیک → حذف + سکوت |
| `قفل هندی` | پیام‌های دارای خط دوناگری → حذف + سکوت |
| `قفل طولانی` | پیامِ بیش از **۱۰۰۰ کاراکتر** → حذف + سکوت |
| `قفل کانال` / `قفل ناشناس` | ارسال با کانال (ناشناس) → حذف + مسدود کردن کانال |

چند نکتهٔ مهم:

* همهٔ این قفل‌ها **پیش‌فرض خاموش** هستند و فقط با دستور مدیر روشن می‌شوند؛
  مدیران طبق معمول از قفل‌ها عبور می‌کنند.
* حدِّ پیامِ طولانی ثابت نیست: در پنل «🔒 قفل‌ها» روی قفلِ «📏 پیام طولانی»
  بزنید و با ➖/➕ مقدارش را تغییر دهید (مقدارِ پیش‌فرض ۱۰۰۰ کاراکتر).
* **برخوردِ پیش‌فرضِ این قفل‌ها «حذف + سکوت»** است و با دستور `برخورد`
  (مثل `برخورد چینی حذف` یا `برخورد طولانی بن`) قابل تغییر است.
* کانال قابل «سکوت» نیست؛ تلگرام فقط `banChatSenderChat` را می‌دهد، بنابراین
  برای کانال‌ها همان مسدود کردن اعمال می‌شود (موقت اگر برخورد سکوت باشد).
* مدیرِ ناشناسِ گروه (Hidden admin) مدیرِ واقعی است، نه یک کانال؛ پیام‌های او
  هرگز حذف نمی‌شوند و فقط پیام‌هایی که با **کانال** فرستاده شوند مشمول این
  قفل هستند.

### 🌍 بن سراسری (GBan)

با `بن سراسری` (فقط مالک ربات) یک شناسه در لیست سیاهِ سراسری قرار می‌گیرد و
ربات آن کاربر را **در همهٔ گروه‌ها و کانال‌هایی که مدیر است** حذف می‌کند:

```
بن سراسری 123456789 تبلیغ        (یا با ریپلای روی پیام کاربر)
رفع بن سراسری 123456789
لیست بن سراسری
```

| مرحله | اتفاق |
| --- | --- |
| لحظهٔ اجرا | کاربر در همان گفتگو بن می‌شود و نتیجه اعلام می‌شود |
| پس‌زمینه | در بقیهٔ گروه‌ها/کانال‌هایی که ربات مدیر است هم بن می‌شود |
| ورودِ بعدی | اگر کاربر دوباره به هر گروه یا کانالی که ربات مدیرش است وارد شود، همان لحظه بن می‌شود |
| پیام دادن | اگر کاربرِ بن‌شده داخل گروه باشد و پیام بدهد، پیامش حذف و خودش بن می‌شود |

چند نکته:

* این قابلیت **پیش‌فرض خاموش** است: `GLOBAL_BAN_ENABLED=true` را در متغیرهای
  محیطی (Railway) تنظیم کنید؛ در غیر این صورت دستور پیام «غیرفعال است» می‌دهد.
* ربات باید در آن گروه/کانال **مدیر و دارای دسترسی «بن کردن اعضا»** باشد؛
  تلگرام آپدیتِ عضویت را فقط به مدیرها می‌فرستد، پس همین شرط برای اجرا کافی است.
* `رفع بن سراسری` هم نام کاربر را از لیست پاک می‌کند و در پس‌زمینه بنِ بقیهٔ
  گفتگوها را هم برمی‌دارد.

### 🔇 سکوت سراسری

مالک ربات می‌تواند از هر چتی این دستور را اجرا کند؛ سکوت سراسری دائمی است و وضعیت
در پایگاه داده می‌ماند تا با `رفع سکوت سراسری` برداشته شود (مدت‌دار نیست):

```
سکوت سراسری 123456789 تبلیغ        (یا با ریپلای روی پیام کاربر)
رفع سکوت سراسری 123456789
لیست سکوت سراسری
```

سکوت در سوپرگروه‌های فعال و ثبت‌شده‌ای اعمال می‌شود که خود ربات در آن‌ها مدیر و
دارای حق «محدودسازی اعضا» باشد و مالک بات نیز در سوپرگروه حضور داشته باشد؛ مدیر
بودن مالک بات الزامی نیست. تلگرام محدودسازی اعضا را فقط در سوپرگروه پشتیبانی
می‌کند؛ کانال و گروه عادی هدف مستقیم این قابلیت نیستند. گروه گفت‌وگوی پیوندخورده
با کانال جداگانه بررسی می‌شود، اگر در فهرست چت‌های شناخته‌شده ثبت شده باشد. ورود
یا پیام بعدیِ کاربرِ ساکت‌شده نیز در سوپرگروه واجد شرایط دوباره بررسی می‌شود.
هنگام رفع سکوت، فقط محدودیت‌هایی برداشته می‌شوند که همین قابلیت اعمال کرده؛
محدودیت محلیِ مدیران حفظ می‌شود.

تلگرام از راه رابط رسمی ربات، فهرست کامل چت‌های بات را ارائه نمی‌کند. ربات چت‌ها
را با رویداد عضویت و به‌روزرسانی‌های دریافتی ثبت می‌کند؛ بنابراین چت‌هایی که پیش‌تر
هیچ‌گاه در پایگاه داده ثبت نشده‌اند، بدون دریافت شناسه/رویداد قابل کشف خودکار نیستند.

### 🔐 واگذاری اختیارات روت

با `دسترسی روت @username` (یا شناسه) در خصوصی، ابتدا چت فعال را انتخاب کنید؛ در
خود گروه هم می‌توانید همان دستور را اجرا کنید. سپس هر اختیار را جداگانه تیک
بزنید. در واگذاری تازه هیچ اختیاری از پیش انتخاب نمی‌شود. فهرست شامل ارسال
همگانی، بن و سکوت سراسری، آمار ربات، مدیریت روت، تأیید/رد گروه و خروج ربات است.

هر دسترسی واگذارشده فقط به چت انتخاب‌شده محدود است و هدف باید در همان چت مدیر یا
سازندهٔ فعلی باشد. اگر اختیار بن/سکوت سراسری انتخاب شود، اثر آن همچنان سراسری است؛
اما دارندهٔ دسترسی فقط از همان چت می‌تواند آن را اجرا کند. واگذاری‌های قدیمی برای
سازگاری فقط اختیار قبلیِ ارسال همگانی را نگه می‌دارند.

### 🔒 پنل اختصاصی هر مدیر

هر مدیری که `پنل` را باز می‌کند، پنل **فقط برای خودش** کار می‌کند. اگر مدیر یا
مالکِ دیگری روی دکمه‌های همان پیام بزند، با یک هشدار رد می‌شود و چیزی تغییر
نمی‌کند؛ هر کس باید پنل خودش را با دستور `پنل` باز کند.

### ↩️ دکمهٔ لغو (Undo)

دستورات برگشت‌پذیر، همراه پیامِ نتیجه یک دکمهٔ شیشه‌ای «لغو» می‌فرستند:

| دستور | دکمه |
| --- | --- |
| `سکوت` | ↩️ لغو سکوت |
| `بن` | ↩️ رفع بن |
| `ارتقا` | ↩️ عزل مدیر |
| `اخطار` | 🗑 کسر اخطار / ♻️ صفر کردن (کارت اخطار) |

هر دکمه قبل از اجرا دوباره دسترسیِ فشاردهنده را از تلگرام استعلام می‌کند،
بنابراین فقط کسی که واقعاً اجازه دارد می‌تواند عمل را برگرداند.

### 🎚 ویرایش دسترسی‌های یک مدیر

با ریپلای روی پیامِ آن مدیر:

| کار | دستور |
| --- | --- |
| ارتقا به مدیر تلگرام | `ارتقا` (یا `ارتقا کامل` برای همهٔ دسترسی‌ها) |
| عزل از مدیریت تلگرام | `تنزل` یا `عزل` |
| ویرایش دسترسی‌ها | `دسترسی مدیر` |

`دسترسی مدیر` یک پنل دکمه‌ای باز می‌کند که هر دسترسی (حذف پیام، بن، دعوت،
سنجاق، تغییر اطلاعات، افزودن مدیر، چت صوتی، ناشناس) را با یک لمس فعال یا
غیرفعال می‌کند و تغییر همان لحظه در تلگرام اعمال می‌شود. پیش‌فرض‌های
«مدیر کامل» و «دسترسی پایه» و دکمهٔ «عزل مدیر» هم در همان پنل هستند.

> تلگرام فقط اجازه می‌دهد ربات دسترسیِ مدیرانی را ویرایش کند که **خودش** آن‌ها
> را ارتقا داده باشد. اگر پیام «توسط ربات منصوب نشده» آمد، یک بار `ارتقا` را
> برای او اجرا کنید؛ بعد از آن دسترسی‌ها قابل ویرایش خواهند بود.

## 🧱 ساختار پروژه

```
armando/
├── app/
│   ├── main.py               # نقطه ورود: Long Polling / Webhook
│   ├── config.py             # تنظیمات از .env (بدون لاگ کردن اطلاعات محرمانه)
│   ├── logging_setup.py      # لاگ ساختاریافته + پنهان‌سازی توکن
│   ├── core/                 # ابزارهای پایه: نرمال‌سازی، زمان، کش TTL، ریت‌لیمیت، خطاها
│   ├── db/                   # مدل‌های SQLAlchemy، ایندکس‌ها، مهاجرت سبک
│   ├── services/             # منطق کسب‌وکار (نظارت، قفل، فیلتر، بازار، کپچا، …)
│   ├── keyboards/            # ساخت دکمه‌ها و منوهای سلسله‌مراتبی رنگی
│   ├── handlers/             # لایه تلگرام: ثبت دستورات، پنل، پیام‌ها، خطاها
│   ├── middlewares/          # نشست دیتابیس، ریت‌لیمیت، ردیابی چت
│   └── data/                 # داده‌های متنی (لیست کلمات، جوک‌ها، فال حافظ …)
├── tests/                    # تست‌های pytest (واحد + یکپارچه با تلگرامِ شبیه‌سازی‌شده)
├── docs/                     # مستندات (فهرست دستورات، معماری)
├── data/                     # دیتابیس (در زیپ منتشر نمی‌شود)
├── requirements.txt  Procfile  railway.toml  Dockerfile  runtime.txt
└── .env.example
```

## 🔐 امنیت و نکات مهم

- هیچ توکن/کلیدی در لاگ‌ها نوشته نمی‌شود (فیلتر خودکار).
- بنِ سراسری (Global Ban) فقط برای مالک ربات است و **پیش‌فرض خاموش** است
  (`GLOBAL_BAN_ENABLED=false`)؛ با روشن شدن، در همهٔ گروه‌ها و کانال‌هایی که
  ربات مدیر است اعمال می‌شود.
- هوش مصنوعی اختیاری است؛ در صورت نبود کلید یا خطای شبکه، بخش نظارت مختل نمی‌شود.
- ربات نمی‌تواند فهرست کامل اعضا را از تلگرام دریافت کند، بنابراین آمارها بر اساس
  داده‌هایی است که از زمان حضور ربات جمع‌آوری شده (در مستندات داخل ربات هم ذکر شده).
- فایل `.env` را هرگز منتشر نکنید؛ خروجی پشتیبان نیز فاقد اطلاعات محرمانه است.
